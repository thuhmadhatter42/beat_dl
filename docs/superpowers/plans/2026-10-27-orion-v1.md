# Orion v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship beat_dl as Orion.app: a signed, notarized, universal Mac app in a DMG. It has one window (paste a YouTube link, click DOWNLOAD, get the renamed MP3 and its BPM/key) styled after Artemis.

**Architecture:** The app is a SwiftUI app built with SwiftPM (no .xcodeproj). It spawns one Python orchestrator, `app_run.py`, which reuses `downloader.py` and `bpm.py` and prints JSON-lines events that the Swift side renders. Every tool (Python 3.11 + Essentia + numpy, ffmpeg/ffprobe, yt-dlp) is pre-extracted per architecture into `Contents/Resources/runtime/<arch>/` at build time and signed with hardened runtime. Writable state, meaning the self-updating yt-dlp and its stamp, lives in `~/Library/Application Support/Orion/`.

**Tech Stack:** Swift 5 / SwiftUI (macOS 11 target, universal), SwiftPM, bash build scripts, the vendored Python 3.11 (`unittest`, no pytest), codesign, notarytool, hdiutil.

**Spec:** `docs/superpowers/specs/2026-10-27-beat-dl-mac-app-design.md` (read it first), with the mockup at `docs/superpowers/specs/orion-v1-mockup.html` as the visual source of truth.

## Global Constraints

- Name **Orion**, bundle ID `com.jshriver.orion`, Application Support `~/Library/Application Support/Orion/`.
- Deployment target **macOS 11.0**, universal (arm64 + x86_64).
- Signing identity `Developer ID Application: J Shriver (9WTFGV63S2)`, notary profile `artemis-notary`. Hardened runtime on every Mach-O.
- The signed bundle is never written to at run time. Set `PYTHONDONTWRITEBYTECODE=1` and precompile `.pyc` before signing.
- `run.command` / `run.sh` behave exactly as before. Any edit to `downloader.py` / `bpm.py` is opt-in via a flag or env var. Default behavior is unchanged.
- Output identical to `run.sh`: the MP3 is saved in `~/Downloads`, renamed `<stem> (<bpm> BPM <k1> <k2> <k3>).mp3` (keys without the `(NN%)`), and the log `~/Downloads/(YY-M-D) Youtube DL LINKS.txt` gets `Input URL: <url>\nDownloaded: <name>\n\n`. If analysis fails, the name stays as it is and the entry is still logged.
- No song/artist/file names in commits, fixtures or logs (J's rule). Test audio is synthesized.
- `VERSION` file at the repo root, starting `0.1.0`. Every build reads it. Bump the last number per edit.
- Look: Artemis tokens. `--amber #ffb020`, green `#3ddc7a`, red `#e2372c`, face font Helvetica Neue, dark only. Never `#000`/`#FFF` as a surface.
- Never restart Sofia. Commands to it go through `~/.claude/scripts/ssh-rc js-mac-pro '<cmd>'`.

## Review Focus

1. **A URL with a playlist or `&t=` / `&list=` params:** it downloads the single video, as `--no-playlist` already does. Test in Task 2.
2. **A title with `/`, `:`, emoji or quotes:** the rename and log still work, and the Swift side shows the name. Test in Task 2 (the stub yt-dlp emits such a title).
3. **The user clicks DOWNLOAD twice or drops a file mid-download:** the second action is ignored while busy, and nothing runs twice. Test in Task 3 (engine rejects `start` while running).
4. **No network:** a plain-English error shows on the LCD in under ~30 s, never a hang. Test in Task 2 (stub yt-dlp exits 1 with a network message → `error` event with `explain_error`'s text).
5. **A dropped non-audio file (a .txt, a folder):** "Couldn't find BPM/key for this one", with no crash. Test in Task 2 (`analyze` on a text file → `analyzed` with `bpm: null`).

### Task 2: `app_run.py`, the orchestrator with JSON events

**Files:**
- Create: `app_run.py`
- Modify: `downloader.py`: add `strategies(app_order: bool) -> list[list[str]]`. With `app_order=True`, return the non-cookie strategies first and the three browser-cookie ones last. `run_download(url, silent=False, app_order=False)` uses it. The CLI default is unchanged.
- Modify: `bpm.py:_tool`: check `os.environ.get("ORION_BIN")` first, then `HERE/bin`, then PATH.
- Create: `tests/test_app_run.py` (`unittest`), `tests/stub/yt-dlp` (a bash stub driven by `STUB_MODE` env: `ok`, `ok-weird-title`, `fail-network`, `fail-then-ok`, `upgrade`)

**Interfaces:**
- CLI: `app_run.py download <url>` and `app_run.py analyze <file>...`. One JSON object per stdout line, flushed. The exit code is 0 unless the process itself crashed.
- Events (exact keys):
  - `{"stage":"downloading"}`, `{"stage":"analyzing"}`, `{"stage":"renaming"}`, `{"stage":"updating"}` (yt-dlp upgrade before the retry)
  - `{"stage":"done","file":"<abs path>","name":"<basename>","bpm":"142.0"|null,"keys":[["Cm",73],["Eb",18],["Gm",9]]|[]}`
  - `{"stage":"analyzed","file":"<abs path>","name":"<basename>","bpm":...|null,"keys":[...]}`, one per dropped file
  - `{"stage":"error","message":"<explain_error text>"}`
- Functions: `renamed_name(stem: str, ext: str, bpm: str, keys: list[tuple[str,int]]) -> str` (run.sh's format), `log_line(url: str, name: str) -> str`, `analyze_file(path: Path, timeout: int = 120) -> tuple[str|None, list]` (runs `bpm.py` as a subprocess with the timeout and parses its 4 lines).
- Upgrade/retry: on a failed download, emit `updating`, run `yt-dlp -U` (the `yt-dlp` on PATH, which the Swift side points at Application Support), retry once, and on a second failure emit `error`.
- The Downloads folder and log path are read from `ORION_DOWNLOADS` (default `~/Downloads`) so tests can use a temp dir.

### Task 3: Swift package and the engine (no UI yet)

**Files:**
- Create: `app/Package.swift` (executable target `Orion`, test target `OrionTests`, platform `.macOS(.v11)`)
- Create: `app/Sources/Orion/Engine.swift`, `app/Sources/Orion/Runtime.swift`, `app/Sources/Orion/Event.swift`
- Create: `app/Tests/OrionTests/EventTests.swift`, `EngineTests.swift`

**Interfaces:**
- `enum Event: Equatable { case stage(String); case done(Result); case analyzed(Result); case error(String) }`, `struct Result: Equatable { let file: URL; let name: String; let bpm: String?; let keys: [(String, Int)] }`, `static func parse(line: String) -> Event?` (unknown or garbage → nil).
- `struct Runtime { let root: URL /* Resources/runtime */; let arch: String /* from sysctl hw.optional.arm64, as deps.sh */; let support: URL /* App Support/Orion */; func environment() -> [String:String]; func seedYtDlp() throws; var needsWeeklyUpgrade: Bool; func upgradeYtDlp() async }`.
  - `environment()`: PATH = `support/bin:root/<arch>/bin:/usr/bin:/bin`, `ORION_BIN=root/<arch>/bin`, `PYTHONDONTWRITEBYTECODE=1`, `PYTHONNOUSERSITE=1`, `PIP_CONFIG_FILE=/dev/null`, with no PYTHONPATH/PYTHONHOME.
  - `seedYtDlp`: copy the bundle's yt-dlp to `support/bin/yt-dlp` if it's missing or won't run (`--version`).
  - `upgradeYtDlp`: `yt-dlp -U`. If the result won't run, re-seed from the bundle. If it runs but was blocked, ad-hoc re-sign `codesign -s - -f` once and re-check. Then touch `support/.last-ytdlp-upgrade`. Weekly = stamp older than 7 days.
- `final class Engine: ObservableObject { @Published var state: ViewState; func download(_ url: String); func analyze(_ files: [URL]) }`. Both are ignored while `state.isBusy`. `ViewState` is `idle | working(stage: String) | done(Result) | analyzed([Result]) | failed(String)`.
